## 2. 핵심 결정 5개와 근거

**① 기반 선택: FastAPI 기반 + Streamlit 기반의 안전장치 4가지 옮김(D1)**
- **정한 것:** Python + FastAPI + Postgres(pgvector) + React + Docker + LangGraph. 외부 호출 전 개인정보 차단, 실데이터 파이프라인, 숫자 대조, 계획 JSON은 Streamlit 기반에서 옮김
- **기준:** 남은 기간과 기능 완성도. 멀티턴·수준별 3단계·피드백 저장·운영 화면·문서 검색이 이미 있어 새로 만들 것이 적음
- **대안:** Streamlit 기반(Python + Streamlit + SQLite + LangGraph). 강점을 옮겨 오는 출처로만 씀

**② 수치는 DB에서만, 숫자 대조, 기준일·고지는 코드가 붙임(설계 원칙)**
- **정한 것:** 답변 속 수치는 DB 조회 결과에서만 옴. 코드가 답변 숫자를 근거와 대조(단위 환산, 반올림·상대 오차 5%, 날짜)하고, 기준일과 투자 고지를 코드가 붙임
- **기준:** LLM이 숫자를 지어내면 금융 답변에서 바로 오류가 되고, 규칙은 프롬프트보다 코드가 확실히 지킴
- **대안:** 프롬프트로 "숫자를 지어내지 말라"고 지시하는 방식([CLAUDE.md](../CLAUDE.md) 설계 원칙 2: 프롬프트에 맡기지 않음)

**③ 사실 비교만 하고, 순위는 정렬 기준·기준일과 함께(D7, 순위 규칙 R1~R3)**
- **정한 것:** 타사 상품도 사실 비교표로 보여 주되 "더 좋다" 같은 평가 표현은 금지. R1 정렬 기준·기준일을 같은 문장에, R2 총보수만으로 "가장 저렴" 금지, R3 순위를 추천으로 잇지 않음([guard_rules.md](guard_rules.md) 6장)
- **기준:** 자사(ACE) 상품이 1개뿐이라 자사만 다루면 비교 기능이 사라짐. 순위가 추천으로 읽히지 않게 함
- **대안:** 자사 상품만 비교. 광고 규제는 고객사 확인 사항으로 남김

**④ 데이터 범위: ETF 5개(D4), 공시 제외(D5), 수동 CSV, 투자설명서 색인 제외(D6)**
- **정한 것:** 나스닥100 비교군 3개(자사 ACE 포함) + 국내 대표 지수 1개 + 배당 1개를 출처·기준일이 있는 수동 CSV로 검증·적재. 공시는 제외, 개념 문서 13개만 색인
- **기준:** 평가에 쓰는 값만 정확히 확보(11-21 범위 조정 2차). 투자설명서는 PDF 표 쪼개기와 보수 숫자 불일치 위험(11-22)
