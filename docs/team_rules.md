# 협업 규칙

이 문서는 저장소 규칙([dev-guide.md](dev-guide.md), [git-flow.md](git-flow.md))을 기준으로 하고, 팀이 더한 규칙만 적습니다. 다르면 저장소 규칙을 따릅니다.

## 1. 브랜치·커밋

- 형식과 타입은 [dev-guide.md](dev-guide.md) 2·3장을 따릅니다. 팀이 더한 타입 `eval`(평가셋·평가 실행기), `test`(테스트만)도 거기에 있습니다.
- 팀 추가: 한 커밋에는 한 가지 변경만 담고, 직접 실행해서 확인한 뒤 커밋합니다.

## 2. PR과 병합

- 기본 흐름(`dev`로 PR, CI 통과 후 작성자 squash 머지)과 릴리스는 [dev-guide.md](dev-guide.md) 4·5장, 따라 하기는 [git-flow.md](git-flow.md)를 봅니다.
- **승인 필수 PR**(개인정보 차단·가드·숫자 대조·데이터 파이프라인)은 [dev-guide.md](dev-guide.md) 4장 "승인이 필수인 PR"을 봅니다.
- 팀 추가
  - **옮겨 온 코드**는 **원 코드 작성자가 리뷰**합니다. **원 코드 작성자나 들여오는 사람이 같으면 다른 팀원 1명이 리뷰**합니다(자기 리뷰 방지).
  - PR 본문에는 관련 작업 카드 번호, 바꾼 것, 확인 방법(명령), 남은 문제를 적습니다.
  - 11-25(수) MVP 이후에는 새 기능 PR을 받지 않습니다(버그·문서·평가만).

## 3. 작업 카드


- **작업 카드(GitHub Issue) 1개 = 담당자 1명 = 브랜치 1개**
- 카드에는 완료 기준을 한 줄 이상 적습니다.
- 막히면 카드에 댓글로 남기고 스탠드업에서 말합니다.

## 4. 키와 비밀값

- 보관 위치(Key Vault·GitHub Secrets·`.env`), 이름 규칙, 등록·교체, 실수로 커밋했을 때는 [dev-guide.md](dev-guide.md) 6장을 따릅니다.
- 팀 추가
  - **채팅·로그·스크린샷에도 키를 넣지 않습니다.**
  - **Azure 키 관리자를 1명 지정합니다**(채팅방 결정, [decision_board.md](decision_board.md)). 관리자가 Key Vault 등록과 팀원 `.env` 전달 방식을 맡습니다.
  - Gemini·Groq 같은 무료 키는 팀원 각자 자기 것을 씁니다. 여러 키를 번갈아 쓰는 코드는 만들지 않습니다(한도 우회 소지).
  - `.env.example`에는 이름과 설명만 두고 값은 넣지 않습니다.

## 5. 커밋 금지 파일

| 대상 | 이유 |
|---|---|
| `.env`, `.env.local` 등 비밀값 파일 | 키 유출 |
| 외부 원본 데이터(KRX 구성종목 CSV, 투자설명서 PDF 등) | 재배포 금지 |
| API 응답 원본 | 각자 자기 키로 생성 |
| DB 파일(SQLite 파일, DB 덤프), 벡터 색인 | 원본으로 각자 생성 |
| LLM 응답 캐시, 사용량 기록 | 개인별 |
| 평가 결과 원본 | 개인별(요약 표만 문서로 커밋) |
| 개인 IDE·Claude Code 로컬 설정 | 개인별 |
| 사용자 테스트 원문(질문·답변 로그) | 질문 원문이 남음 |

- 팀이 공개 자료를 보고 직접 적은 수동 값(총보수 등)과 출처는 원본이 아니므로 커밋합니다.
- 커밋 전에 `git status`로 위 파일이 없는지 확인합니다. 위 항목은 `.gitignore`에 들어 있습니다.

## 6. 테스트

- `pytest`는 **mock으로만** 돌립니다. 실제 LLM·임베딩·외부 데이터 API를 부르지 않습니다(크레딧과 무료 한도 보호).
- 실제 모델 확인은 손 테스트나 평가 실행기로만 하고, 실행 전에 비용을 계산합니다.

## 7. 크레딧과 사용량

- **예산 알림:** Azure 구독에 단계별 예산 알림을 켭니다(Cloud Engineer).
- **하루 질문 상한:** 공개 URL에는 하루 질문 수 상한을 두고, 넘으면 안내 문구를 보여 줍니다. 상한 값은 비용 계산으로 정합니다.
- **평가 전 비용 확인:** 평가를 돌리기 전에 질문당 토큰 × 문항 수로 비용을 계산하고 남은 크레딧과 비교합니다.
- 남은 크레딧과 모델별 토큰은 스탠드업에서 공유합니다.

## 8. 데이터

- **크롤링 금지.** 공식 API(공공데이터포털, OpenDART)와 사람이 직접 내려받은 파일만 씁니다.
- 모든 값에 출처와 수집일, 항목별 기준일을 남깁니다.
- 실제 데이터가 없으면 누가 봐도 가짜인 샘플만 쓰고, 파일명에 `SAMPLE`을 넣습니다.

## 9. 개인정보

- **개인정보(주민·외국인등록번호, 카드, 계좌, 전화, 이메일)는 모든 외부 API 호출(LLM, 임베딩) 전에 차단합니다.**
- 차단된 질문은 외부 호출이 0회인지 테스트로 확인합니다.
- 저장하는 대화·피드백은 마스킹하고, 로그에는 질문 원문을 남기지 않습니다.

## 10. 도구 규약

- 린트·포맷·검사(`make check`)는 [dev-guide.md](dev-guide.md) 1·8장을 따릅니다.
- 팀 추가: 웹 화면(TypeScript) 린트와 Python 버전은 코드 들여오기 뒤 Cloud Engineer가 맞춥니다([roles.md](roles.md) 4장).

## 11. 소통

- 매일 15분 스탠드업: 어제 한 것, 오늘 할 것, 막힌 것, 남은 크레딧
- 결정은 [decisions.md](decisions.md)에 기록합니다. 결정이 바뀌면 그 문서를 먼저 고칩니다.
